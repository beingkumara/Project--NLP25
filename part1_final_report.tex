    \begin{abstract}
    This report works through the NLP assignment step by step. Part 1 builds a small toy IR system by hand, covering the inverted index, TF-IDF weights, Boolean retrieval, and cosine similarity ranking. Parts 2--5 then move to the Cranfield dataset, where we implement and compare seven retrieval systems ranging from a basic VSM baseline all the way to BM25, LSA, PRF, query expansion, and ESA variants.     \end{abstract}

    % ===========================================================================
    \section{Introduction}
    % ===========================================================================

    The basic idea in information retrieval is that you have a large pile of documents and a user has some question or need --- the job of the system is to find which documents are actually useful to them. Matching on keywords alone works surprisingly often, but it completely falls apart whenever the user and the document author chose different words for the same concept. This happens constantly in technical writing.

    The standard baseline for IR is the Vector Space Model (VSM), where every document is turned into a vector of term weights and ranked against a query vector using cosine similarity. VSM is easy to implement and runs fast, but it has one strong assumption built into it: every word in the vocabulary is treated as a completely separate, independent dimension. The model has no idea that \textit{heated} and \textit{thermal} are related concepts --- so if the query uses one and the relevant document uses the other, the system completely misses the connection. On narrow technical datasets where specialist synonyms are everywhere, this causes a lot of failures.

    This report covers all five parts of the assignment. Part~1 works through a toy three-document IR system entirely by hand, going step by step through the inverted index, TF-IDF weights, Boolean retrieval, and cosine similarity ranking. Parts~2 and~3 scale this up to the Cranfield aerodynamics dataset and evaluate the VSM baseline using six standard metrics (Precision, Recall, F$_{0.5}$, MAP, nDCG, MRR). Part~4 analyses where the baseline fails and why, with specific examples from the actual data. Part~5 proposes and evaluates six improved retrieval systems --- BM25, LSA, WordNet query expansion, BM25 with pseudo-relevance feedback, and two ESA variants --- and uses the Wilcoxon Signed-Rank Test to check whether measured improvements are statistically real or just noise.

    \subsection{Preprocessing and Inverted Index}

    The three source documents are as follows: $d_1$: \textit{``The star in our solar system provides heat and light.''}, $d_2$: \textit{``That Hollywood star walked the red carpet for the movie premiere.''}, and $d_3$: \textit{``Astronomers observe distant stars and galaxies using telescopes.''}

        \item $d_2$: \texttt{[that, hollywood, star, walked, the, red, carpet, for, the, movie, premiere]}
        \item $d_3$: \texttt{[astronomers, observe, distant, stars, and, galaxies, using, telescopes]}

    \subsection{Boolean Retrieval}

    Query: \textit{``star light''}. Looking up the inverted index: \texttt{star} $\to \{d_1, d_2\}$, \texttt{light} $\to \{d_1\}$. Boolean AND (intersection) yields $\mathbf{d_1}$ as the sole matching document. With Boolean OR we would retrieve $d_1 \cup d_2$, but AND is the standard default for multi-term queries.

    \subsection{Cosine Similarity and Ranking}

    The query vector $\mathbf{q}$ has non-zero entries only for \textit{star} ($0.176$) and \textit{light} ($0.477$), giving $\|\mathbf{q}\| = \sqrt{0.176^2 + 0.477^2} \approx 0.508$.

    \[
    \mathrm{Cosine}(q, d_1) = \frac{(0.176)^2 + (0.477)^2}{0.508 \times \sqrt{0.176^2 + 5 \times 0.477^2}} = \frac{0.2585}{0.508 \times 1.081} \approx \mathbf{0.470}
    \]
    \[
    \mathrm{Cosine}(q, d_2) = \frac{(0.176)^2}{0.508 \times \sqrt{0.176^2 + 6 \times 0.477^2}} \approx \frac{0.031}{0.600} \approx \mathbf{0.051}
    \]
    \[
    \mathrm{Cosine}(q, d_3) = 0 \quad \text{(no shared terms)}
    \]

    \begin{itemize}[noitemsep]
        \item \textbf{Final ranking:} $d_1 \succ d_2 \succ d_3$, with cosine similarities 0.470, 0.051, and 0 respectively.
        \item \textbf{Is the ranking desirable?} Yes. The query \textit{``star light''} is about starlight as a physical phenomenon. $d_1$ discusses the Sun providing heat and light — a direct match. $d_2$ only shares the token \textit{star} used in the celebrity sense, so its score (0.051) is much lower, and it is correctly demoted. $d_3$ scores zero because it has no query terms at all.
    \end{itemize}

    \subsection{Word Sense Ambiguity}

    Query: \textit{``movie star''}.

    \begin{itemize}[noitemsep]
        \item \textbf{Which document(s) should ideally be retrieved?} Only $d_2$, which describes a Hollywood film premiere --- the ``celebrity'' sense of \textit{star} matches exactly. $d_1$ and $d_3$ are irrelevant.

        \item \textbf{Does the system retrieve the correct document(s)?} Not exclusively. After stopword removal the query terms are \textit{movie} (IDF = 0.477) and \textit{star} (IDF = 0.176). Computing cosine similarity gives $d_2 \approx 0.431$ and $d_1 \approx 0.056$ --- so $d_1$ is also returned with a non-zero score, even though it has nothing to do with celebrities. The system fails to restrict retrieval to the correct document.

        \item \textbf{How does word sense ambiguity affect retrieval?} The TF-IDF model assigns the same token \textit{star} to both $d_1$ (astronomical star) and $d_2$ (celebrity). Because both documents contain this token, both receive a non-zero score from the query. This is the classical \textbf{polysemy} problem: the bag-of-words representation cannot separate the two word senses, so the system returns an irrelevant document alongside the correct one, degrading precision.
    \end{itemize}

    \section{Part 2: Building an IR System — Implementation}
    % ===========================================================================

    \subsection{TF-IDF Vector Space Model}

    The retrieval pipeline was implemented in \texttt{informationRetrieval.py} following the standard Vector Space Model (VSM). The implementation uses an inverted index (a dictionary mapping every vocabulary term to its per-document raw term frequency) combined with augmented TF weighting and standard IDF:

    \[
    w(t, d) = \underbrace{\left(0.5 + 0.5 \cdot \frac{\mathrm{tf}(t,d)}{\max_{t'}\mathrm{tf}(t',d)}\right)}_{\text{augmented TF}} \times \underbrace{\log_{10}\!\left(\frac{N}{\mathrm{df}(t)}\right)}_{\text{IDF}}
    \]

    Augmented TF prevents longer documents from dominating by normalising raw term counts against the most frequent term in the same document. Documents are ranked by cosine similarity in the resulting vector space. The implementation handles out-of-vocabulary (OOV) terms gracefully: when a query term is unseen, its IDF lookup returns zero and the term contributes nothing to the dot product.

    The same preprocessing pipeline was applied uniformly to both queries and documents before indexing:
    \begin{itemize}[noitemsep]
        \item Punkt sentence segmentation
        \item Penn Treebank tokenisation
        \item WordNet lemmatisation
        \item NLTK stopword removal
    \end{itemize}

    \subsection{Dataset: The Cranfield Collection}

    Cranfield is one of the oldest IR test collections around and it is still widely used as a benchmark. It has 1400 documents --- short abstracts from aeronautics research papers --- and 225 queries representing actual information needs in the domain. Each query comes with relevance judgements (qrels) that record how useful each relevant document is, on a four-point scale from very relevant (position~1) down to marginally relevant (position~4). All other documents that do not appear in the qrels are treated as non-relevant.

    For all our experiments, relevance is treated as binary: any document with a qrel position of 1, 2, 3, or 4 counts as relevant. The only exception is the graded nDCG metric reported in Part~5, where positions 1--2 receive gain~2 and positions 3--4 receive gain~1.

    One thing that makes Cranfield particularly useful for this assignment is that it is a very narrow, specialised domain. All 1400 abstracts use highly technical aerodynamics vocabulary --- terms like \textit{laminar flow}, \textit{transonic regime}, and \textit{aeroelastic flutter} --- which general-purpose resources like WordNet were not built to handle. Because the vocabulary mismatch problem is both severe and measurable in this dataset, it is a good test bed for comparing IR methods that try to go beyond simple keyword matching.

    \section{Part 3: Evaluating the IR System}
    % ===========================================================================

    \subsection{Evaluation Measures}

    Six evaluation measures were implemented in \texttt{evaluation.py}:

    \textbf{Precision@k} counts the fraction of retrieved documents in the top-$k$ that are truly relevant:
    $\mathrm{Precision@k} = |\{d \in R_k \mid d \in \mathcal{R}\}| / k$.

    \textbf{Recall@k} measures what proportion of all relevant documents were retrieved in the top-$k$:
    $\mathrm{Recall@k} = |\{d \in R_k \mid d \in \mathcal{R}\}| / |\mathcal{R}|$.

    \textbf{F$_{0.5}$-score@k} uses the general $F_\beta$ harmonic mean formula:
    $F_\beta = \frac{(1+\beta^2) \cdot P \cdot R}{\beta^2 \cdot P + R}$.
    Substituting $\beta = 0.5$ ($\beta^2 = 0.25$) gives $F_{0.5} = \frac{1.25 \cdot P \cdot R}{0.25P + R}$, which weights precision twice as heavily as recall.

    \textbf{Average Precision (AP@k)} rewards systems that place relevant documents early in the ranking. For a query with $|\mathcal{R}|$ total relevant documents,
    $\mathrm{AP@k} = \frac{1}{|\mathcal{R}|} \sum_{i=1}^{k} \mathrm{Precision@i} \cdot \mathbf{1}[\mathrm{doc}_i \in \mathcal{R}]$,
    where $\mathbf{1}[\mathrm{doc}_i \in \mathcal{R}] = 1$ if the document at rank $i$ is relevant and 0 otherwise --- so only ranks that actually hit a relevant document contribute to the sum.

    \textbf{nDCG@k} normalises the Discounted Cumulative Gain against the ideal ordering. Unlike precision-based metrics, DCG is designed for \emph{graded} relevance: the numerator $\mathrm{rel}_i$ is the relevance grade of the document retrieved at rank $i$ (for Cranfield, this is the qrel position value 1--4, or 0 if not in the qrels), and the denominator $\log_2(i+1)$ is the positional discount --- a relevant document at rank 1 contributes more than the same document at rank 5. $\mathrm{DCG@k} = \sum_{i=1}^{k} \frac{\mathrm{rel}_i}{\log_2(i+1)}$, and $\mathrm{nDCG@k} = \mathrm{DCG@k} / \mathrm{IDCG@k}$. In our main evaluation we use the binary simplification $\mathrm{rel}_i \in \{0,1\}$ (qrel positions 1--4 all treated as equally relevant, as required by the assignment); the graded variant nDCG@10$^*$ in Table~\ref{tab:comparison} restores grades 2 and 1 for qrel positions 1--2 and 3--4 respectively.

    \textbf{Mean Reciprocal Rank (MRR@k)} measures how early the first relevant document appears. For each query the reciprocal rank is $1/r$ where $r$ is the position (within the top-$k$) of the first relevant document, or 0 if none is found. $\mathrm{MRR@k} = \frac{1}{|Q|} \sum_{q} \frac{1}{r_q}$.

    Relevance was determined by the Cranfield qrels: documents with a position value of 1, 2, 3, or 4 were treated as relevant.

    \textbf{MAP@10: 0.2691.} \quad \textbf{MRR@10: 0.7028.}
    Mean Reciprocal Rank at cutoff $k$ gives the average, over all 225 queries, of $1/r$ where $r$ is the rank of the first relevant document found within the top-$k$ results (0 if none appears). At $k{=}1$, MRR collapses to Precision@1 = 0.6000 because the only available rank is 1. MRR@10 = 0.7028 tells us that on most queries the first relevant document was found at rank 1 or 2. For the queries where rank 1 was wrong, the system still managed to get a relevant document into rank 2 or 3 in most cases, which is why MRR is noticeably higher than Precision@1.

    \subsection{Observations from the Plots}

    \textbf{Precision vs.\ $k$} declines monotonically from 0.60 at $k{=}1$ to 0.25 at $k{=}10$. This is the standard precision–recall trade-off: expanding the result window retrieves more relevant documents but necessarily also more irrelevant ones, diluting precision.

    \textbf{Recall vs.\ $k$} increases monotonically, from 0.105 to 0.371. Because the Cranfield queries have an average of roughly 8 relevant documents each, a cutoff of $k{=}10$ captures just over a third of all relevant material — indicating substantial room for improvement.

    \textbf{F$_{0.5}$-score} peaks at $k{=}3$ (0.333) and then declines, reflecting the higher weight placed on precision. Once precision degrades past a certain point, the combined score falls even though recall continues to improve.

    \textbf{MAP vs.\ $k$} rises gradually from 0.10 at $k{=}1$ to 0.27 at $k{=}10$. Each time a relevant document is retrieved at a new position, it adds a precision-at-that-position value to the AP sum, so MAP can only go up or stay flat as $k$ grows.

    \textbf{nDCG vs.\ $k$} moves in the \emph{opposite} direction: it decreases from 0.60 at $k{=}1$ to approximately 0.42 at $k{=}10$, then plateaus. At $k{=}1$ there is only one rank position, so nDCG collapses to Precision@1 = 0.60 (the system either placed a relevant document first or it did not). As $k$ grows, additional non-relevant documents accumulate in the ranked list, adding nothing to the DCG numerator while the ideal DCG denominator continues to grow, so the ratio falls. The plateau near 0.42 past $k{=}5$ shows diminishing change — most of the useful signal is already captured in the top five positions.

    \textbf{MRR vs.\ $k$} rises quickly at first and then levels off sharply. At $k{=}1$ it equals Precision@1 = 0.600 because there is only one possible rank position and MRR either gets $1/1$ or $0$. From $k{=}1$ to $k{=}3$ it jumps to 0.680 --- a gain of 0.080 in just two steps --- because this is where most of the ``second-chance'' queries are resolved: queries whose first relevant document sits at rank 2 or 3 now contribute a non-zero reciprocal rank. After $k{=}3$ the curve nearly flattens: MRR only improves by 0.023 over the remaining seven positions ($k{=}3$ to $k{=}10$), reaching 0.703. This plateau tells us that very few queries have their first relevant document sitting beyond rank 3. In other words, for the queries where the system does eventually find a relevant document, it almost always places it in the top three positions. Queries that have no relevant document in the top 3 but find one further down contribute very small reciprocal ranks ($1/4$, $1/5$, \ldots) that barely move the aggregate average.

    \subsection{Run Time}

    The complete pipeline (loading, preprocessing 1400 documents and 225 queries, building the inverted index, ranking all queries, and computing all six evaluation metrics) completed in approximately \textbf{4.4 seconds}, demonstrating the efficiency of the sparse inverted-index approach.

    \section{Part 4: Analysis — Limitations of the VSM}
    % ===========================================================================

    \subsection{Vocabulary Mismatch and the Assumption of Orthogonality}

    The VSM treats every word as a completely separate, independent dimension. Two words that mean the same thing are treated as having nothing in common. This assumption breaks down badly when the query and the relevant document use different but related vocabulary, which happens a lot in technical domains. A good example from our own results: consider the query \textit{``what similarity laws must be obeyed when constructing aeroelastic models of heated high speed aircraft''} and Document 29, which discusses \textit{``transient temperatures and thermal stresses in simple models intended to simulate parts of an aircraft structure subjected to aerodynamic heating.''}

    The qrels mark Document 29 as highly relevant (position 2). Yet our TF-IDF system placed it at \textbf{rank 109}. The cause is a direct vocabulary mismatch: the query uses \textit{heated}, while Document 29 uses \textit{thermal}, \textit{temperatures}, and \textit{heating}. Since these are distinct word types in the vector space, the dot product receives no contribution from this conceptual overlap, and the cosine similarity collapses to near zero.

    This is not an edge case. The Cranfield corpus is composed of highly technical aerodynamics abstracts, where synonymy between specialist terms (e.g., \textit{velocity} vs.\ \textit{speed}, \textit{pressure} vs.\ \textit{stress}, \textit{viscous} vs.\ \textit{viscid}) is pervasive. The Bag-of-Words assumption is particularly damaging in this domain.

    \subsection{The Out-of-Vocabulary (OOV) Problem}

    When a query contains no terms that appear in the document corpus, the query vector reduces to the zero vector. Every document then scores a cosine similarity of exactly zero, and the ranking degenerates to whichever arbitrary order the documents were loaded in. In practice, the system would return $[1, 2, 3, 4, 5, \ldots]$ — a meaningless artefact of file order.

    A controlled test confirmed this behaviour. When we queried with \textit{``intergalactic chennai super kings''} --- a phrase with no meaningful connection to the aeronautics domain --- the top-5 documents returned were \texttt{[438, 1, 2, 3, 4]}. Document 438 ranked first purely because the word \textit{super} happens to appear in it (its title reads ``stagnation point heat transfer measurements at super satellite speeds''), giving it a small but nonzero cosine score. The terms \textit{intergalactic}, \textit{chennai}, and \textit{kings} are entirely absent from the vocabulary, so they contribute nothing to any document's score. Documents 1, 2, 3, 4 then fill the remaining positions in file-load order, each with a cosine similarity of exactly zero. So what we are seeing here is not retrieval at all --- it is just a coincidence that ``super'' happened to survive preprocessing, plus whatever order the documents were loaded in. For a mixed query like \textit{``aerodynamics of intergalactic chennai super kings''}, only \textit{aerodynamics} and \textit{super} do anything useful, and the entire intent behind the remaining terms is simply lost.

    \subsection{Additional Limitations}

    Beyond vocabulary mismatch and OOV, the VSM has three further structural problems:

    \begin{itemize}[noitemsep]
        \item \textbf{Word order blindness.} The model treats \textit{boundary layer} and \textit{layer boundary} as identical because it only counts tokens, not their positions. Document structure (titles, headings, abstracts) is also completely discarded.
        \item \textbf{Length bias.} Even with augmented TF normalisation, a document twice as long still has roughly twice the opportunity to accumulate term matches. So a long document with moderate relevance can outscore a short, tightly-focused one just because it has more words.
        \item \textbf{Negation blindness.} The query \textit{``without turbulence''} produces the same token set as \textit{``with turbulence''}, so both produce the same query vector. There is simply no way in this model to say one word cancels out another.
    \end{itemize}

    \subsection{Introduction and Problem Framing}

    The failure analysis in Part 4 shows a clear and measurable problem: the VSM gets MAP@10 of only 0.2691 on Cranfield, and for Query 1, Document 29 was placed at rank 109 even though the qrels mark it as highly relevant. The root cause is the orthogonality assumption, where every word type gets its own independent dimension regardless of meaning overlap. Our working hypothesis is that if we can somehow make the retrieval model aware of synonymy or co-occurrence relationships between terms, it should be able to fix at least some of these failures.

    To check this, we implemented and evaluated six alternative retrieval systems against the same 225 queries and 1400 documents. For deciding whether any improvement is actually real and not just noise, we use the Wilcoxon Signed-Rank Test on per-query Average Precision values. AP is chosen as the per-query unit because it summarises the full ranked list for one query in a single number — it rewards finding relevant documents and finding them early, making it more informative than a single cutoff metric like Precision@10. It also produces one value per query per system, which is exactly what a paired test needs: 225 matched pairs, one per query. For methods where theory predicts a clear improvement (BM25, LSA, PRF), we use a one-sided test. For methods whose direction of effect is uncertain (query expansion, ESA), we use a two-sided test, which is the statistically correct choice when no directional prior exists.

    \subsection{Proposed Approaches}

    \subsubsection{Method A — BM25 (Okapi BM25)}

    \textit{\textbf{Formulation:} Took Okapi BM25 over Cranfield (1400 documents, 225 queries) under the assumption that TF saturation and length normalisation better model term informativeness than augmented TF-IDF, across Precision@k, Recall@k, MAP@k, nDCG@k (binary and graded), and MRR@k. Hyperparameters $k_1 \in \{1.2, 1.5, 2.0\}$ and $b \in \{0.5, 0.75, 0.9\}$ selected by 5-fold cross-validation.}

    BM25 replaces augmented TF with a saturating TF weighting and a length-normalised document model, addressing two systematic weaknesses of TF-IDF. The scoring function for a term $t$ in document $d$ is:

    \[
    \mathrm{score}(d, Q) = \sum_{t \in Q} \mathrm{IDF}^*(t) \cdot \frac{\mathrm{tf}(t,d) \cdot (k_1 + 1)}{\mathrm{tf}(t,d) + k_1\!\left(1 - b + b \cdot \frac{|d|}{\mathrm{avgdl}}\right)}
    \]

    where $\mathrm{IDF}^*(t) = \log\!\left(\frac{N - \mathrm{df}(t) + 0.5}{\mathrm{df}(t) + 0.5} + 1\right)$ (Robertson IDF, always positive). The parameter $k_1$ controls TF saturation (a term appearing 100 times in a document is not 100$\times$ more relevant than one appearing once) and $b$ controls the degree of length normalisation. Hyperparameters $k_1$ and $b$ were selected by 5-fold cross-validation on query-level MAP, with the grid $k_1 \in \{1.2, 1.5, 2.0\}$ and $b \in \{0.5, 0.75, 0.9\}$. The optimal configuration found was $k_1{=}2.0$, $b{=}0.9$, indicating that on this aerodynamics corpus heavier TF saturation and stronger length normalisation are beneficial, likely because the document collection has high variance in abstract length.

    \subsubsection{Method B — Latent Semantic Analysis (LSA)}

    \textit{\textbf{Formulation:} Took LSA (Truncated SVD) over Cranfield under the assumption that the $k$-rank approximation of the TF-IDF term-document matrix captures latent semantic structure that reduces vocabulary mismatch, across the same measures. The number of latent dimensions selected from $\{50, 100, 200, 300\}$ by 5-fold cross-validation.}

    LSA decomposes the TF-IDF term-document matrix $M \in \mathbb{R}^{V \times N}$ using Truncated Singular Value Decomposition into $M \approx U_k \Sigma_k V_k^\top$. Each document is represented by its corresponding \emph{column} in $\Sigma_k V_k^\top$ (a $k$-dimensional latent vector). A query is projected into the same space by the folding-in operation $\mathbf{q}_{\mathrm{lsa}} = \mathbf{q}_{\mathrm{tfidf}} U_k$, implemented via \texttt{sklearn}'s \texttt{TruncatedSVD.transform()}, which applies the left-singular-vector matrix $U_k$ to map the query from vocabulary space into the $k$-dimensional latent space. Both queries and document vectors are then L2-normalised before cosine similarity is computed, so rankings depend only on direction in the latent space.

    In the $k$-dimensional latent space, terms that consistently co-occur in similar documents are pushed close together even if they never literally co-occur in the same sentence. This directly addresses the vocabulary mismatch problem: \textit{heated} and \textit{thermal} will have nearby latent representations because they appear in documents that share many other technical terms.

    The number of latent components $k$ is a critical hyperparameter. We ran 5-fold cross-validation over $k \in \{50, 100, 200, 300\}$ on query-level MAP to select the best $k$ without leaking test-set information. The CV selected $k{=}200$. We also ran a full ablation on all 225 queries for the purpose of plotting the MAP-vs-$k$ curve, shown below:

    \subsubsection{Method C — VSM with WordNet Query Expansion}

    \textit{\textbf{Formulation:} Took VSM with WordNet Query Expansion over Cranfield under the assumption that first-synset WordNet synonyms (at most 3 per query term) bridge vocabulary gaps without introducing excessive query drift, across the same measures.}

    Query Expansion (QE) attempts to address vocabulary mismatch at query time rather than corpus time. For each token in the preprocessed query, synonyms are retrieved from the primary WordNet synset (at most 3 per word, to avoid query drift). These synonyms are appended as additional query tokens and scored through the existing TF-IDF index.

    The key risk is \emph{query drift}: if the first synset is ambiguous (e.g., \textit{star} retrieving astronomy synonyms for a query about celebrities), the expanded terms pollute the result. This risk is especially acute for short, ambiguous queries.

    \subsubsection{Method D — BM25 with Pseudo-Relevance Feedback (PRF)}

    \textit{\textbf{Formulation:} Took BM25 with Pseudo-Relevance Feedback (top-3 first-pass documents assumed relevant, top-3 new terms injected into a second BM25 pass) over Cranfield under the assumption that the first-pass top documents are sufficiently on-topic to provide useful expansion vocabulary, across the same measures.}

    PRF combines BM25 for initial retrieval with an automatic query expansion step. The top 3 documents from the first BM25 pass are assumed relevant, and the 3 most frequent new terms from those documents are injected into a second BM25 pass. This allows the system to adapt vocabulary to the domain of the query — for instance, a query about \textit{boundary layers} might expand to include co-occurring terms like \textit{laminar}, \textit{turbulent}, and \textit{separation}.

    The central limitation is the same as for QE: if the initial top-3 documents are irrelevant, the feedback terms will actively mislead the second pass (query drift). Our failure analysis confirmed this for queries in low-density relevance regions of the corpus.

    \subsubsection{Method E and F — Explicit Semantic Analysis (ESA)}

    \textit{\textbf{Formulation (Method E):} Took ESA with WordNet concept space over Cranfield under the assumption that WordNet synsets form a useful concept basis for aerodynamics text, with document/query vectors built by TF-IDF-weighted synset activations, across the same measures.}

    \textit{\textbf{Formulation (Method F):} Took ESA with Cranfield concept space over Cranfield under the assumption that the 1400 Cranfield documents themselves form a coherent concept basis (each document treated as a concept dimension), which avoids domain mismatch, across the same measures.}

    ESA projects both documents and queries into a high-dimensional \emph{concept space} rather than word space. We tested two concept spaces: (E) a WordNet synset space, where each synset is a concept dimension, and (F) a Cranfield-internal concept space, where each document is itself treated as a concept (the document-level ESA variant). In both cases, a document's weight for concept $c$ accumulates the TF-IDF weight of every term in the document that maps to $c$. Ranking is by cosine similarity in the concept space.

    The intuition is that two documents describing similar phenomena will activate similar sets of concepts even if they use different surface vocabulary.

Metrics are computed at cutoffs $k{=}1$ to $k{=}10$. No information from qrels was used during system construction (no supervised feedback). Both BM25 hyperparameters ($k_1$, $b$) and LSA's $n\_components$ were each selected by independent 5-fold cross-validation on the query set, with no access to qrel labels during CV. We also report MRR@10 (Mean Reciprocal Rank), which is particularly informative for navigational queries where the first relevant document matters most, and graded nDCG@10 where position~1--2 qrel entries contribute gain~2 and position~3--4 entries contribute gain~1.

    \subsection{Statistical Significance Testing}

    We use the Wilcoxon Signed-Rank Test (non-parametric; no Gaussian assumption required) on per-query AP@10 distributions, with significance level $\alpha = 0.05$. Crucially, we apply a \textbf{one-sided} test ($H_1$: method $>$ baseline) only for methods where theory provides a strong directional prior (BM25, LSA, PRF). For methods where the direction of change is not guaranteed (VSM+QE, ESA), we apply a \textbf{two-sided} test, which is statistically correct when no directional assumption is justified. Using one-sided tests for all methods, as is sometimes done, would mask the significance of harm from degrading methods.

    \textbf{Formal hypothesis framing:}

    \begin{itemize}[noitemsep]
        \item $H_0$: The per-query AP scores of method $X$ and the VSM baseline come from the same distribution.
        \item $H_1^{>}$ (one-sided): Method $X$ produces \emph{strictly higher} AP scores (BM25, LSA, PRF).
        \item $H_1^{\neq}$ (two-sided): Method $X$ produces \emph{significantly different} AP scores (QE, ESA).
    \end{itemize}

    Effect sizes are measured by Cohen's $d = \bar{\delta} / \sigma_\delta$ on the paired differences, where $\bar{\delta}$ is the mean difference and $\sigma_\delta$ is the standard deviation of differences. By Cohen's (1988) conventional benchmarks, $|d| < 0.2$ is negligible, $0.2 \le |d| < 0.5$ is small, $0.5 \le |d| < 0.8$ is medium, and $|d| \ge 0.8$ is large.

    The density breakdown exposes a leadership inversion: \textbf{BM25} leads the sparse-density class (0.4820) but \textbf{BM25+PRF} leads the medium and dense classes (0.3557 and 0.2626). This matches what we saw in the Marginal Difference Analysis: PRF's expansion step depends on reliable first-pass retrieval, and that becomes more likely when many relevant documents are spread across the collection. The MAP numbers also drop consistently as density increases --- this is a structural property of the metric itself. A query with only 2 relevant documents needs just 2 hits in the top-10 for MAP = 1.0, while a query with 20 relevant documents can at best score around 0.49 at $k{=}10$ under perfect retrieval. So MAP comparisons across density classes need to account for this built-in ceiling difference.

    \subsection{Discussion: Why the Methods Work (or Fail)}

    The main pattern across all results is whether a method's assumptions actually fit the Cranfield domain. Here is a per-method breakdown with supporting data:

    \begin{itemize}

    \item \textbf{BM25 worked} because the two things it adds over TF-IDF directly address problems we actually see in Cranfield. The TF saturation means a term appearing 50 times is not scored $50\times$ higher than one appearing once, which is more realistic. The length normalisation stops long abstracts from winning just by having more words. Cross-validation picked $k_1{=}2.0$ and $b{=}0.9$, both above the usual defaults of 1.5 and 0.75, which makes sense because Cranfield abstracts vary a lot in length. MAP went from 0.2691 to 0.3304, a gain of 22.8\%. BM25 improved 142 queries out of 225 and hurt only 37, so the improvement is broad and not just a few lucky queries.

    \item \textbf{LSA worked} because Cranfield is a very narrow domain, so there is enough consistent co-occurrence signal across the 1400 documents for SVD to pick up on. Words like \textit{heated} and \textit{thermal} end up close together in the 200-dimensional latent space because they appear in documents sharing the same aerodynamics vocabulary. We tested $k \in \{50, 100, 200, 300\}$ and MAP peaked at $k{=}200$ (0.3233). Going to 300 actually dropped it slightly to 0.3205, so the extra dimensions started adding noise. The 5-fold cross-validation also independently picked $k{=}200$ without seeing the test labels.

    \item \textbf{BM25 + PRF worked on queries with many relevant documents, but not sparse ones.} PRF assumes the top-3 documents from the first pass are relevant and pulls new terms from them. When a query has 10 or more relevant documents, BM25 usually places at least one in the top-3, so the expansion terms are on-topic. But when there are only 1--3 relevant documents, the first-pass results may all be wrong and PRF gets actively misled. The numbers confirm this: PRF beat plain BM25 on 43 of 67 dense-qrel queries (64.2\%) but only on 5 of 35 sparse-qrel queries (14.3\%). PRF's overall MAP advantage of 0.83\% exists because Cranfield has nearly twice as many dense queries as sparse ones.

    \item \textbf{WordNet Query Expansion hurt performance} because WordNet was not designed for 1950s aerodynamics vocabulary. Words like \textit{aeroelastic} or \textit{blasius equation} do not appear in WordNet at all, and terms like \textit{viscous} get mapped to everyday English meanings (thick, sticky) that are useless for aerodynamics retrieval. Adding these wrong synonyms pushed relevant documents down. QE degraded 130 queries while improving only 28, nearly a 5:1 ratio in the wrong direction. The two-sided Wilcoxon test confirms it is significantly worse than baseline ($p = 8.1 \times 10^{-13}$, mean AP drop of $-0.039$).

    \item \textbf{ESA with WordNet concepts failed} for the same reason as QE. The synset space was designed for general English, so technical Cranfield terms like \textit{laminar} or \textit{oblique shock} either have no synsets at all or they map to general-language concepts that do not connect the right documents. ESA-WordNet hurt 120 queries while helping only 60, and MAP dropped to 0.2115 which is below the baseline of 0.2691. The two-sided Wilcoxon test also confirms this is significantly worse ($p = 4.0 \times 10^{-9}$).

    \item \textbf{ESA with Cranfield concepts worked better than WordNet ESA} because here the concept space was built from the same 1400 documents, so every specialised term in the corpus has a meaningful representation based on how it is actually used. There is no domain mismatch. It still did not beat BM25 or LSA because projecting into 1400 dimensions introduces a lot of noise, but it reached MAP = 0.2963 which is clearly above both WordNet ESA (0.2115) and the baseline (0.2691). It improved 120 queries and degraded 71.

    \end{itemize}

    \subsection{Summary of Findings}

    \begin{enumerate}[noitemsep]
        \item All six methods are statistically significantly different from the VSM baseline (Wilcoxon, $p < 0.05$). Four improve it; two degrade it.
        \item BM25 ($k_1{=}2.0$, $b{=}0.9$, CV-selected) and BM25+PRF are the most practically reliable: highest per-query improvement rates (142 and 136 improved queries), fewest new failures (1 and 4), and strong aggregate metrics.
        \item The MAP gap between BM25 (0.3304), BM25+PRF (0.3388), and LSA (0.3233) is marginal ($<1.6\%$) and does not constitute a credible superiority claim without pair-level tests. Per-query analysis shows BM25+PRF wins on more individual queries than BM25.
        \item VSM+QE and ESA-WordNet are statistically significantly \emph{worse} than the baseline, not merely indistinguishable — a distinction only visible when using the correct two-sided Wilcoxon test.
        \item The number of LSA latent dimensions is best selected by 5-fold CV ($k{=}200$, CV MAP = 0.3233). Selecting $k$ on all 225 test queries constitutes data leakage; CV gave the same answer here, but the methodology matters.
        \item MRR and graded nDCG provide complementary insight: BM25 leads on first-relevant-position quality (MRR = 0.8002); BM25+PRF leads on surfacing the most highly relevant documents (graded nDCG = 0.4887).
        \item The vocabulary mismatch case study confirms that all three corpus-based methods (BM25, LSA, PRF) partially address the core failure, but none fully resolves it.
    \end{enumerate}

    \section{Conclusion}
    % ===========================================================================

    This project built and evaluated an Information Retrieval system on the Cranfield aerodynamics dataset, starting from a TF-IDF Vector Space Model baseline and testing six alternative retrieval approaches. The baseline VSM achieved MAP@10 = 0.2691 and nDCG@10 = 0.4203. The main problem identified was the orthogonality assumption, which caused vocabulary mismatch failures like Document 29 being placed at rank 109 for Query 1 despite being clearly relevant.

    Six alternative systems were tested. BM25 ($k_1{=}2.0$, $b{=}0.9$, hyperparameters selected by 5-fold cross-validation) gave the most consistent improvement: MAP@10 = 0.3304 (+22.8\% relative), Wilcoxon $p = 3.3 \times 10^{-16}$, Cohen's $d = 0.57$ (medium effect), improving 142 out of 225 queries and degrading only 37. BM25+PRF achieved MAP@10 = 0.3388 with the best graded nDCG (0.4887), and LSA at $k{=}200$ (selected by 5-fold CV to avoid data leakage) achieved MAP@10 = 0.3233. All three are statistically significantly better than the baseline.

    Importantly, the correct application of two-sided Wilcoxon tests for VSM+QE and ESA-WordNet revealed that they are not merely indistinguishable from the baseline — they are statistically significantly \emph{worse} ($p < 10^{-8}$). This distinction matters: one-sided tests had previously masked the harm these methods cause.

    The overall takeaway is that methods which rely on the corpus itself (BM25's statistics, LSA's SVD, PRF's feedback) worked, while methods that import outside knowledge from WordNet failed because the domain mismatch was too large. One direction to explore further would be transformer-based dense retrieval, which learns semantic representations directly from text rather than depending on a hand-built lexical resource like WordNet.
